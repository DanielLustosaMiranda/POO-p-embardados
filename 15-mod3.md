# Módulo 3: Herança, Polimorfismo e Sistemas Não-Bloqueantes

Até agora nosso robô consegue andar e fazer curvas. Mas temos um problema crítico quando usamos `delay()`.
Se quisermos que o robô pisque um LED enquanto anda, como faríamos?
Se colocarmos um `delay(500)` para o LED, o motor também vai ficar travado nesse delay! O robô não conseguirá reagir a um sensor ou mudar de direção rapidamente. Esse é o clássico problema de código bloqueante.

Para resolver isso, precisamos de um sistema não-bloqueante. E para fazer isso de forma elegante, vamos usar dois conceitos muito poderosos da Orientação a Objetos: **Herança** e **Polimorfismo**.

## Herança

Herança é a capacidade de uma classe herdar atributos e métodos de outra classe. Isso evita repetição de código e cria uma hierarquia lógica.
Vamos criar uma classe base (ou classe "Mãe") chamada `ComponenteVisual`. A partir dela, vamos criar classes filhas, como `LedSimples` e `LedPiscante`.

A ideia é que todo componente visual tem coisas em comum: um pino e a capacidade de ser "atualizado" a cada ciclo do loop.

## Polimorfismo e Sistemas Não-Bloqueantes

O Polimorfismo (do grego, "várias formas") permite que tratemos objetos de classes diferentes como se fossem do mesmo tipo da classe base. A mágica acontece quando dizemos para a classe base atualizar, e cada classe filha sabe exatamente como se atualizar da sua própria maneira.

Vamos ver na prática. Primeiro a classe base:

```cpp
#include <Arduino.h>

class ComponenteVisual {
protected: // protected permite que as classes filhas acessem os atributos, mas o resto do mundo não
    int pino;
public:
    ComponenteVisual(int pino) : pino(pino) {
        pinMode(pino, OUTPUT);
    }
    
    // Método virtual puro. Isso torna a classe base abstrata.
    // Obriga todas as classes filhas a implementarem esse método!
    virtual void atualizar() = 0; 
};
```

Agora vamos criar um `LedSimples` que apenas acende:

```cpp
// LedSimples herda de ComponenteVisual
class LedSimples : public ComponenteVisual {
public:
    LedSimples(int pino) : ComponenteVisual(pino) {}

    // Implementação do atualizar para o LedSimples
    void atualizar() override {
        digitalWrite(pino, HIGH); // Apenas mantém ligado
    }
};
```

E agora a estrela do show, o `LedPiscante`, que usa `millis()` para não travar o robô:

```cpp
class LedPiscante : public ComponenteVisual {
private:
    unsigned long tempoAnterior;
    unsigned long intervalo;
    bool estadoAtual;

public:
    LedPiscante(int pino, unsigned long intervalo) : 
        ComponenteVisual(pino), intervalo(intervalo), tempoAnterior(0), estadoAtual(false) {}

    // O LedPiscante sabe como se atualizar sozinho sem usar delay!
    void atualizar() override {
        unsigned long tempoAtual = millis();
        if (tempoAtual - tempoAnterior >= intervalo) {
            tempoAnterior = tempoAtual;
            estadoAtual = !estadoAtual; // inverte o estado
            digitalWrite(pino, estadoAtual);
        }
    }
};
```

## A Mágica da Atualização (Polimorfismo na prática)

No nosso `main.cpp` (ou mesmo dentro da classe `Robo`), podemos criar um "Array de Ponteiros" para `ComponenteVisual`. Nós guardamos todos os componentes visuais em uma lista, e no `loop()`, mandamos todos se atualizarem com apenas *uma única linha de código*!

```cpp
// Array de ponteiros para a classe base
ComponenteVisual* meusLeds[2];

void setup() {
    // Instanciamos as classes filhas e guardamos no array da classe base
    meusLeds[0] = new LedSimples(2);
    meusLeds[1] = new LedPiscante(4, 500); // Pisca a cada 500ms
}

void loop() {
    // Esse for é o Polimorfismo trabalhando por nós.
    // O sistema descobre sozinho em tempo de execução qual comportamento (LedSimples ou LedPiscante) deve executar!
    for (int i = 0; i < 2; i++) {
        meusLeds[i]->atualizar();
    }
    
    // Agora os motores podem rodar livres aqui sem serem bloqueados!
}
```

> **Dúvidas Comuns:**
> 
> **Por que usar ponteiros e a palavra `new`?**
> Em C++, para que o Polimorfismo funcione em arrays ou variáveis em tempo de execução, precisamos usar ponteiros (ou referências) para a classe base. O `new` aloca dinamicamente o objeto na memória e nos dá um ponteiro para ele.
>
> **O que é o `override`?**
> É uma palavra-chave que diz ao compilador "Ei, estou reescrevendo um método virtual que veio da minha classe mãe". Ajuda a evitar erros de digitação (como digitar `atuaizar()`), porque o compilador vai te alertar se não bater com a assinatura exata da classe base.
