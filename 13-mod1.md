# Módulo 1: Classes, Objetos e Encapsulamento:

O que é Orienteção a Objetos, classes, objetos e encapsulamento? 

Orientação a objetos é um paradigma de programação orientado a objetos é um paradigma de programação que utiliza objetos para modelar e resolver problemas.

# Classes e objetos. 

Na robótica, esse objetivo de modelar o mundo real para resolver problemas se encaixa perfeitamente. Como vocês já sabem, nossos robôs são compostos por diversos componentes eletrônicos como motores, sensores, LEDs e etc. E cada um desses componentes podem ser modelados como objetos.
E como objetos, conseguimos definir suas caracteristicas, funções e comportamentos.

As Classes são conjuntos de objetos que compartilham propriedades e comportamentos. 
Exemplo: A classe "Carro" é um conjunto de objetos que compartilham propriedades e comportamentos como ter 4 rodas, acelerar, frear, etc. 

Objetos são instâncias de classes. 
Exemplo: Um "Fiat Uno", um "VW Gol", etc. Ambos são objetos da classe "Carro".

Um objeto possui atributos e métodos.

Os atributos se referem ao estado do objeto, como por exemplo, a cor de um led. 
Os métodos se referem ao comportamento do objeto, como por exemplo, ligar ou desligar um led.

# Encapsulamento

Encapsulamento é um conceito de orientação a objetos que diz respeito à capacidade de agrupar e proteger dados e funções em uma única entidade. Basicamente ele permite que você esconda os detalhes de implementação de uma classe, expondo apenas o que for necessário.

# Construtor

Um construtor é um método especial que é chamado quando um objeto é criado. Ele é usado para inicializar os atributos do objeto.
Em palavras mais simples, é uma função especial para quando eu declarar o objeto consiguir atribuir valores a ele. Usando o exemplo do carro, a classe carro poderia ter um construtor que recebe a cor do carro e o modelo do carro, e atribui esses valores aos atributos cor e modelo do objeto.

Vamos ver isso na prática:

Esses conceito é similar a struct de C, apenas com algumas diferenças. Em C struct era basicamente um agrupamento de dados. Em C++ é um agrupamento de dados e funções. No caso de struct, os atributos e métodos são públicos por padrão. Outra diferença crucial é que as classes suportam o conceito de encapsulamento, que permite ocultar detalhes de implementação e proteger dados.
Revisão rapida de uma struct:
```c
// como criar uma struct para amazernar dados como o de uma pessoa
// Idade, nome, altura, peso, etc.
#include <stdio.h>
typedef struct {
  int idade;
  char* nome;
  float altura;
  float peso;
} Pessoa;

// como acessar esses dados ou modificar:
Pessoa joao = {25, "Joao", 1.75, 70.0};
joao.idade = 26;
printf("Nome: %s\n", joao.nome);
printf("Idade: %d\n", joao.idade);
printf("Altura: %.2f\n", joao.altura);
printf("Peso: %.2f\n", joao.peso);
```

## Prática: Criar a classe Led.

Problema inicial: Faça sua ESP32 acender 3 leds com comportamentos diferentes. 1- Apenas acender, 2- Piscar, 3- Acender lentamente e apgar lentamente.

Vamos resolver isso de duas maneiras distintas. A primeira maneira é usando apenas funções e a segunda maneira é usando classes. 
Criem um arquivo chamado main.cpp e vamos resolver o problema de ambas as maneiras. 

Eu sei que alguns não sabem acender um led, por isso eu vou explicar o funcinamento disso para vocês. 
Um LED é um diodo que emite luz na passagem de corrente elétrica por ele. 
A corrente elétrica só consegue atravessar o LED em uma única direção. 
Por isso, para acender um led, precisamos conectar um terminal do led ao pino da esp32 e o outro terminal ao terra. 
Além disso, precisamos garantir que a tensão seja compatível. A esp32 fornece 3,3V, enquanto muitos leds operam com 2V. 
Portanto, é preciso colocar um resistor em série para limitar a corrente. O valor do resistor deve ser de aproximadamente 220 ohms. 

Voce faz a ligação do circuito nos pinos de GPIO da esp32 e coloca no código.
Agora vamos resolver o problema efetivamente:

```cpp
#include <arduino.h>

// definimos os pinos onde os leds estão conectados
#define LED1 2
#define LED2 4
#define LED3 15

void acenderBrilhando(int pino){
   for (int brilho = 1; brilho <= 255; brilho *= 2) {
    analogWrite(pino, brilho);
    delay(1000);
   }
}

// void setup realiza apenas a inicialização dos pinos
void setup(){
   pinMode(LED1, OUTPUT);
   pinMode(LED2, OUTPUT);
   pinMode(LED3, OUTPUT);
}


// void loop realiza o comportamento que o robô deve executar
// No caso aqui estamos acendendo e apagando os leds em loop, cada um com um comportamento diferente
void loop(){

   // Acender o led 2
   digitalWrite(LED2, HIGH);

   // Pisccar o led 1
   digitalWrite(LED1, HIGH);
   delay(1000);
   digitalWrite(LED1, LOW);
   delay(1000);

   // Acender o led 3 lentamente e apagar lentamente
   acenderBrilhando(LED3);

}
```
Uma breve explicação sobre o digitalWrite e o analogwrite. Digital o valor vai de 0 1, porque é digital já no analógico o valor vai de 0 a 255, onde 255 é o máximo de brilho, 127 é a metade do brilho e 0 é o mínimo de brilho.
Antes um exercicio. Quais comportamentos o LED vai fazer? Quais as caracteristicas do led? Isso vai nos orientar a como estruturar a classe.
É de se esperar ouvir algo como: "o led vai acender, apagar e piscar.". Ótimo.

```cpp
#include <Arduino.h>

#define PINO2 2
#define PINO4 4
#define PINO15 15

class LED{

// O private define atributos privados, ou seja, que não podem ser acessados por outras classes
private:
  int pino;

// O public define atributos públicos, ou seja, que podem ser acessados por outras classes
public:
   
   // contrutor da classe LED 
  LED(int pino) : pino(pino) {}

  void begin(){
    pinMode(pino, OUTPUT);
  }

  void ligar(){
    digitalWrite(pino, HIGH);
  }
  
  void desligar(){
    digitalWrite(pino, LOW);
  }
  
  void alternar(){
    digitalWrite(pino, !digitalRead(pino));
  }
  
  void acenderBrilhando(){
   for (int brilho = 1; brilho <= 255; brilho *= 2) {
    analogWrite(pino, brilho);
    delay(200);
   }
  }
};

LED ledVermelho(LED_VERMELHO);
LED ledAmarelo(LED_AMARELO);
LED ledVerde(LED_VERDE);

// void setup realiza apenas a inicialização dos pinos
void setup(){
   ledVermelho.begin();
   ledAmarelo.begin();
   ledVerde.begin();
}

// void loop realiza o comportamento que o robô deve executar
// No caso aqui estamos acendendo e apagando os leds em loop, cada um com um comportamento diferente
void loop(){
   ledVermelho.ligar();
   ledAmarelo.alternar();
   ledVerde.acenderBrilhando();
  
}
```

Um questionamento que possa aparecer. Porque o pino é privado? O que acontece se eu colocar o pino como publico? Posso fazer isso?
Sim, você pode fazer isso. Mas não é uma boa prática, pois viola o conceito de encapsulamento. O motivo de encapsular é justamente não deixar que outras classes tenham acesso direto aos atributos da classe. 
Neste exemplo, não faz muita diferença, pois temos apenas uma classe e os pinos são definidos no início do programa.
A idea de encapsular é proteger, porque a propria classe vai ser um bloco isolado que sabe do seu funcinamento interno, das suas estruturas e isso impede que em algum outro lugar do código você insira um dado invalido. 
Exemplo: 
```cpp
class LED{
public:
  int pino;
  void ligar(){
    digitalWrite(this->pino, HIGH);
  }
  void desligar();
}

void loop(){
  // qualquer coisa pode alterar esse pino
  ledAmarelo.pino = 10;

}
```

Se o atributo está privado e se eu quisesse mudar ele de pino, eu não conseguiria? Sim, conseguiria. 
```cpp
class LED{

// O private define atributos privados, ou seja, que não podem ser acessados por outras classes
private:
  int pino;

// O public define atributos públicos, ou seja, que podem ser acessados por outras classes
public:
   
   // contrutor da classe LED 
  LED(int pino) : pino(pino) {}

  int getPino(){
    return pino;
  }

  void setPino(int pino){
    this->pino = pino; // O 'this->' é obrigatório aqui!
  }

  void begin(){
    pinMode(pino, OUTPUT);
  }

  void ligar(){
    digitalWrite(pino, HIGH);
  }
  
  void desligar(){
    digitalWrite(pino, LOW);
  }
  
  void alternar(){
    digitalWrite(pino, !digitalRead(pino));
  }
  
  void acenderBrilhando(){
   for (int brilho = 1; brilho <= 255; brilho *= 2) {
    analogWrite(pino, brilho);
    delay(200);
   }
  }
};
```

> **Dúvida comum: Funciona se eu usar `pino = pino;` na função setPino?**
> **Não funciona!** Se você escrever apenas `pino = pino;`, o compilador C++ vai olhar para a variável com esse nome mais "próxima" a ele no escopo, que é o próprio parâmetro da função (`int pino`). Ele vai simplesmente pegar o valor do parâmetro e guardar dentro do próprio parâmetro, ignorando completamente o atributo da classe. 
> 
> O `this->` é uma palavra-chave que funciona como um ponteiro para o próprio objeto. Usar `this->pino` avisa o C++: *"Estou falando do atributo 'pino' DESTA CLASSE, e não do parâmetro que acabei de receber"*. 
> Uma alternativa comum para não precisar usar o `this->` é dar nomes diferentes, como `void setPino(int novoPino) { pino = novoPino; }`.
> 
> **Mas então por que no construtor `LED(int pino) : pino(pino)` funciona sem o `this->`?**
> Isso acontece por causa da sintaxe especial chamada **Lista de Inicialização** (`: atributo(parametro)`). Nessa parte específica do código (logo após os dois pontos e antes das chaves `{}` do construtor), o C++ aplica uma regra rígida: ele *sabe* obrigatoriamente que o nome que está fora dos parênteses só pode ser um atributo da classe que está sendo inicializado. Já o nome que está dentro dos parênteses é avaliado normalmente, apontando para o parâmetro recebido. Como essa área foi desenhada exatamente para isso, o compilador não se confunde e o `this->` não é necessário.
